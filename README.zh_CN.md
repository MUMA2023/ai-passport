# 家机桌宠 —— 住在桌面上的小伙伴

[English](README.md) | 简体中文

「家机桌宠」是运行在 FoloToy AI Passport 上的一款固件应用。它把设备变成一只待在桌面上的小宠物：会呼吸、会小幅走动、会眨眼，会饿、会困，也会记住你们相处了多久。

开机即进入桌宠，没有启动器也没有菜单。

## 它是什么

- **是伙伴，不是菜单。** 通电之后宠物已经在屏幕里等着了。
- **它有心情。** 表情、状态文案和音效都跟着当前心情走，一眼就能看出它是平静、好奇、开心、兴奋、饿了、犯困、寂寞还是睡着了。
- **三件事可以做。** 撸一撸、喂食、玩耍。三种互动的收益不同，也都可能被拒绝——宠物会告诉你原因。
- **它会记住你。** 亲密度、各项次数、饱腹、精力、若干计时器以及时钟都会写进 NVS，拔电不会让关系归零。存档采用双槽 + CRC 校验，写入过程中掉电也不会损坏记录。
- **它会自己累。** 醒着时精力持续下降；精力过低就会睡着，睡着后回充速度远快于消耗，然后自己醒来。饱腹在醒着时衰减，睡着时暂停。
- **时钟与电量。** 左上角是时钟，右上角是电量。电量读不到时宁可留空，也不显示编造的数字。
- **音效反馈。** 开机、撸一撸、喂食、玩耍、饿了、入睡、醒来、移动、确认、拒绝各有一段短音效。音调全部由代码合成，固件里没有任何音频素材文件。

## 操作

| 按键 | 操作 | 效果 |
| --- | --- | --- |
| 上 | 短按 | 撸一撸。增加亲密度，但每 5 秒只能撸一次。 |
| 下 | 短按 | 喂食。回复饱腹；已经很饱时会拒绝。 |
| 确定 | 短按 | 玩耍。消耗精力和少量饱腹；太累或太饿时会拒绝。 |
| 确定 | 长按 | 打开状态页。 |

| 页面 | 按键 | 效果 |
| --- | --- | --- |
| 状态页 | 确定 短按 | 打开时钟页。 |
| 状态页 | 确定 长按 | 返回桌宠主界面。 |
| 时钟页 | 上/下 短按 | 以分钟为单位调整时钟。 |
| 时钟页 | 确定 长按 | 保存并返回主界面。 |

## 行为规则

行为是一台纯逻辑状态机，放在 [`main/pet_model.c`](main/pet_model.c)，完全不碰硬件，因此可以在电脑上直接跑测试。下表里的数值都是可调参数，名字都在 [`main/pet_model.h`](main/pet_model.h) 里。

| 项目 | 数值 |
| --- | --- |
| 初始饱腹 / 精力 | 70 / 80 |
| 饱腹衰减 | 醒着时每 90 秒掉 1 点 |
| 精力消耗 | 醒着时每 120 秒掉 1 点 |
| 精力回复 | 睡着时每 20 秒回 1 点 |
| 入睡阈值 | 精力 ≤ 15 |
| 唤醒阈值 | 精力 ≥ 90 |
| 感到寂寞 | 超过 600 秒没有互动 |
| 喂食 | 饱腹 +35，饱腹 ≥ 85 时拒绝 |
| 玩耍 | 精力 -18、饱腹 -5，需要精力 ≥ 25 且饱腹 ≥ 20 |
| 撸一撸 / 喂食 / 玩耍 的亲密度 | +3 / +2 / +5 |
| 亲密度等级 | 陌生 0、熟悉 20、亲近 60、挚友 120 |

宠物睡着时所有互动都会被拒绝，所以乱按按钮叫不醒它——它按自己的节奏醒。

## 断电保存

状态保存在 NVS 的 `desk_pal` 命名空间下，分 `slot_a` 与 `slot_b` 两个槽位交替写入。每次保存都把另一槽写上递增的序号和覆盖整条记录的 CRC32。开机时读两个槽，取校验通过且序号更大的那一份，因此写入被打断也总能留下一份可用数据。

每次互动后都会保存，另外每 30 秒保存一次。落盘由后台任务完成，队列深度为 1，所以按键处理和界面绘制都不会被 Flash 写入卡住。

一个如实的限制：设备没有实时时钟芯片。时钟只在固件运行期间走，下次开机会从上次保存的值继续，因此除非你到时钟页校准，否则它会一直偏。

## 编译

需要 **ESP-IDF 5.5.3**，即设备基线锁定的版本。工具链见[环境搭建](docs/development/engineering/environment-setup.zh_CN.md)，完整流程见[构建与测试](docs/development/engineering/build-and-test.zh_CN.md)。

```bash
./tools/validate.sh --static     # 仓库检查 + 主机测试
./tools/validate.sh --firmware   # ESP-IDF 构建 + 合并 0x0 镜像
```

固件检查会产出 `build/FoloToy-AI-Passport-full.bin`，即从 `0x0` 烧录的完整镜像。

如果仓库所在的路径含有非 ASCII 字符，编译时要关掉 ccache（`export IDF_CCACHE_ENABLE=0`）。ccache 是 C++ 程序，它对路径的转换会抛 `filesystem error: Cannot convert character sequence: Illegal byte sequence`，导致每一个编译单元都失败。ESP-IDF 默认启用 ccache。

中文字体是生成出来的，不是手工提交的。它是按应用实际会渲染的字符裁剪出的子集，这样就不必在 8 MB Flash 里塞进一整套中文字库：

```bash
python3 tools/gen_pet_font.py --font /path/to/NotoSansSC-VF.ttf
```

改动了 `main/` 里任何中文文案后都要重新跑一次。Noto Sans SC 使用 SIL Open Font License 1.1 授权。

字体过期是**静默失败**：那个字直接渲染成空白，而编译、仓库检查和主机测试全都是绿的。所以 `./tools/validate.sh --static` 会执行 `tools/check_font_coverage.py`，只要有 `main/` 里用到的字符在字体里找不到字形，就判定门禁不通过。**「需要哪些字」由校验脚本自己独立扫描得出，而不是复用生成器的收集结果**——否则收集函数本身漏字时两边会一起错，U+2026「…」当初就是这么漏掉的。该检查同时校验 LVGL 依赖的字体结构——稀疏 cmap 的偏移必须有序且不超出 `range_length`、`glyph_id_start` 必须连续、cmap 覆盖的字数必须与字形描述表一致。

## 目录结构

| 路径 | 内容 |
| --- | --- |
| `main/pet_model.h` / `.c` | 纯逻辑状态机：衰减、心情、亲密度、时钟格式化。不依赖硬件。 |
| `main/pet_store.h` / `.c` | NVS 双槽持久化，带 CRC32 与后台写入任务。 |
| `main/pet_audio.h` / `.c` | 代码合成音效与播放任务。 |
| `main/pet_view.h` / `.c` | LVGL 界面：房间场景、宠物本体、状态气泡、亲密度条、顶部信息条、状态页、时钟页。 |
| `main/pet_app.h` / `.c` | 编排层：唯一一个任务持有模型与界面，按键和每秒心跳只负责入队。 |
| `main/lv_font_pet_16.c` | 生成出来的 2bpp 中文子集字体；字形数据是 const，放在 Flash 里。 |
| `main/main.c` | 启动：拉起 I2C、显示与 LVGL，然后交给应用。 |
| `tools/gen_pet_font.py` | 字体生成脚本。 |
| `tools/check_font_coverage.py` | 校验生成的字体是否仍覆盖 `main/` 中用到的全部字符。 |
| `tests/test_pet_model.c` | 状态机的主机测试，由 `./tools/validate.sh --static` 执行。 |

BSP 参考演示仍然参与编译——这样它们不会在无人察觉的情况下被改坏——但已经不在启动路径上，链接时会被丢弃，不进固件。

## 线程模型

应用为状态保持单一归属：所有模型读写与 LVGL 调用都发生在同一个任务里。按键回调和每秒一次的定时器跑在共享基础设施上，因此它们只把消息塞进队列就立刻返回。LVGL 不是线程安全的，任务访问界面时仍会持有 BSP 提供的 LVGL 锁。
